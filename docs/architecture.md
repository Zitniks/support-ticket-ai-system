# Архитектура (черновик)

```mermaid
flowchart TD
    A[Mobile / Web<br/>Каналы обращения пользователя] --> B[API<br/>Приём запроса, синхронно]
    A -.->|поле «категория проблемы»,<br/>указывается пользователем| G[Доп. признак: категория<br/>оплата / доставка / аккаунт и т.п.]
    B --> C[Очередь<br/>Буфер перед моделью]
    C --> D[Модель классификатор<br/>Определяет тип и риск тикета]
    G -.->|доп. входной признак<br/>наравне с текстом| D
    D --> E[Очередь LLM с RAG<br/>Генерация ответа]
    D --> F[Очередь к support admin<br/>Ручной разбор проблемы]
```

С фронта (веб/приложение) вместе с текстом тикета приходит поле «категория проблемы» — пользователь сам указывает, к чему относится обращение (оплата, доставка, аккаунт и т.п.). Это дополнительный признак на входе классификатора, наравне с текстом тикета, а не замена самой классификации: финальную категорию и риск определяет модель и они могут отличаться от значения, указанного пользователем.
